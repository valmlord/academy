# Итоговый проект: движок слотов на Go

**Твой шаг.** В эталонном плане урока 1 движок это часть срезов 1, 2, 3 и 6: правила недельного
расписания (REQ-01, REQ-05, REQ-07), дни перевода часов и исключения дат (REQ-02, REQ-03, REQ-04),
буферы, уведомление и окно бронирования (REQ-06, REQ-08, REQ-09) и отменённые бронирования
(REQ-10). Номера REQ здесь и ниже из спецификации стартера, в своей нумерации они могут быть
другими. Вертикальная команда писала бы движок по кусочку внутри каждого из этих срезов. Здесь он
пишется целиком и за одним швом, `bin/slots`, без HTTP: так его можно проверить как чёрный ящик, а
сервер урока 4 возьмёт готовый пакет.

## Проблема

Первая версия движка на Go обычно выглядит так: окно "09:00-11:00" превращается в момент через
`time.Date(год, месяц, день, 9, 0, 0, 0, пояс)`, следующий день получается через
`Add(24 * time.Hour)`, слоты сравниваются через `==`. В обычный день всё сходится с примерами.

Ломается это в дни перевода часов. Документация `time.Date` говорит прямо: "A daylight savings
time transition skips or repeats times", и в таких случаях "Date returns a time that is correct in
one of the two zones involved in the transition, but it does not guarantee which." Правило Ирины
другое и однозначное: время в разрыве читается по смещению до перевода, из двух повторов берётся
первый. Значит, `time.Date` не может решать за вас, какой момент выбрать.

С днями то же самое. День перевода длится 23 или 25 часов, и `Add(24 * time.Hour)` в такой день
уводит окно на час. Про `AddDate` документация пишет: "AddDate(0, 0, 1) applied to 12:00 on March
27 always returns 12:00 on March 28. At some locations and in some years this is a 24 hour shift.
In others it's a 23 hour shift".

## Идея: местное время превращается в момент явно

Движок работает с двумя видами времени. Местная дата и "HH:MM" из расписания это ещё не момент.
Момент (`time.Time`) появляется, когда вы решили, какое смещение действует. Это решение принимает
ваш код, по правилу Ирины, в одном месте: в функции, которая по местной дате, минутам от полуночи и
поясу возвращает момент.

Как выбрать смещение:

1. Запишите местное время как будто в UTC: `wall := time.Date(y, m, d, 0, minutes, 0, 0, time.UTC)`.
   `minutes` = 1440 для `24:00` даст полночь следующей даты: "October 32 converts to November 1",
   так `time.Date` нормализует значения вне диапазона.
2. Узнайте смещение пояса за сутки до и через сутки после `wall`. В поясах курса смещение меняется
   не чаще раза в такой промежуток, поэтому смещений не больше двух.
3. Для каждого смещения кандидат это `wall.Add(-offset)`. Кандидат годится, если в его момент пояс
   действительно имеет это смещение.
4. Годных два: это повтор, берите более ранний. Годный один: обычное время. Ни одного: это разрыв,
   берите кандидата по смещению "до".

Смещение в момент `t` даёт `t.In(loc).Zone()`: "Zone computes the time zone in effect at time t,
returning the abbreviated name of the zone (such as "CET") and its offset in seconds east of UTC."

Проверим на дне из урока 1. 8 марта 2026 года в Нью-Йорке в 02:30 смещения -05:00 и -04:00.
Кандидат 07:30 UTC: в этот момент уже -04:00, не годится. Кандидат 06:30 UTC: ещё -05:00, тоже не
годится. Разрыв, берём смещение "до": 07:30 UTC, то есть 03:30 по летнему времени.

Дни перебирайте по местной дате, а не по моментам: дата плюс один через `AddDate(0, 0, 1)` на
полуночи в UTC, без часов и поясов. День недели берите от этой же даты. Внимание: у Go
"A Weekday specifies a day of the week (Sunday = 0, ...)", а в расписании понедельник 1 и
воскресенье 7.

## Как это видно в коде

Короткая программа, её можно запустить у себя (`go run main.go`):

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	berlin, err := time.LoadLocation("Europe/Berlin")
	if err != nil {
		panic(err)
	}

	saturday := time.Date(2026, 3, 28, 9, 0, 0, 0, berlin)
	fmt.Println(saturday.AddDate(0, 0, 1))    // 2026-03-29 09:00:00 +0200 CEST
	fmt.Println(saturday.Add(24 * time.Hour)) // 2026-03-29 10:00:00 +0200 CEST

	first := time.Date(2026, 10, 25, 0, 30, 0, 0, time.UTC).In(berlin)
	second := first.Add(time.Hour)
	fmt.Println(first, second)       // 02:30 CEST и 02:30 CET
	fmt.Println(first.Equal(second)) // false: это разные моменты
}
```

Сравнивайте моменты через `Equal`, `Before`, `After`. Про `==` документация предупреждает: "the
Go == operator compares not just the time instant but also the Location and the monotonic clock
reading". Один и тот же момент в поясе Берлина и в UTC через `==` не равен.

Дальше всё считается на моментах, как в спецификации: окно от resolve(начало) до resolve(конец),
кандидаты через `Add` с шагом в минутах, конфликты с буферами на полуоткрытых интервалах,
уведомление и окно бронирования от `now`. Здесь `Add` правильный: шаг слотов и окно бронирования
в спецификации заданы в прошедших минутах и сутках по 24 часа.

> **Go для TS-разработчика.**
> - **Модули.** `backend/go.mod` начинается с `module calendar` и `go 1.27`. Импорт пакета внутри
>   модуля пишется от имени модуля: `"calendar/internal/slots"`, как путь от корня в `tsconfig`
>   `paths`. Строка `go` это минимум: "Go toolchains refuse to use modules declaring newer Go
>   versions". Не поднимайте её выше версии в образе (1.27).
> - **`vendor/` вместо `node_modules`, которого нет в git.** Сторонние модули Go скачивает из сети.
>   Проверка собирает без сети, поэтому сторонний модуль нужен в `vendor/`: `go mod vendor`
>   "constructs a directory named `vendor` ... containing copies of all packages needed to build and
>   test packages in the main module", и если `vendor/` есть, а строка `go` не ниже 1.14, "the go
>   command acts as if -mod=vendor were used". Для движка достаточно стандартной библиотеки.
> - **`time.Date` и пояса.** Пояс загружает `time.LoadLocation("Europe/Berlin")`. `time.Date` в
>   разрыве и повторе выбирает момент сам, и какой, не гарантирует (см. выше).
> - **`nil`-срез и `null`.** Пустой результат в Go часто `nil`-срез, а `encoding/json` пишет его
>   как `null`: "a nil slice encodes as the null JSON value". Готовая обвязка `cmd/slots` уже
>   заменяет `nil` на `[]`; если перепишете её, сохраните это.

## Частые ошибки

- Момент окна через `time.Date` в поясе расписания: в разрыве Нью-Йорка и в повторах Берлина и
  Сиднея результат расходится с правилом Ирины. Проверяйте оба полушария: в одном полушарии ошибка
  может не проявиться.
- Следующий день через `Add(24 * time.Hour)`.
- День недели как `int(t.Weekday())`: воскресенье станет 0, а не 7. Или день недели от даты в UTC.
- Шаг слотов от начала часа, а не от начала окна: окно 09:15 даёт 09:15, 09:45, а не 09:30.
- Последний слот, который кончается ровно в конце окна, отброшен из-за `<` вместо `<=`.
- Буферы проверены только с одной стороны или касание интервалов считается пересечением.
- Отменённое бронирование всё ещё занимает время.
- `==` вместо `Equal` в своём тесте: тест красный на верном коде, если ожидаемые слоты записаны
  со смещением, а движок вернул UTC.
