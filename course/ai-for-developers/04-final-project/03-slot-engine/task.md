# Задание: движок слотов на Go за швом `bin/slots`

Время: около 105 минут (около 90 из них практика):

- теория 15;
- случаи в `testdata/slots/` 20;
- реализация 55: местное время в момент с разрывом и повтором 20, перебор дат с исключениями 10,
  кандидаты с конфликтами и буферами 15, уведомление и окно бронирования 5, подключение к готовой
  обвязке `cmd/slots` 5;
- цикл "запустить проверку, поправить" 15.

Можно перенести свою работу поверх стартера, проверки одинаковы. Копировать стартер следующего
урока можно, но это не упражнение: проверка тогда ничего о вас не скажет.

## Что в рабочей папке

Эталонное состояние урока 2: бриф, интервью, глоссарий, `docs/spec.md` с требованиями и
примерами, ADR, план срезов, контракт в `contract/`. Новое:

- `backend/cmd/slots/main.go`: готовая обвязка `bin/slots`. Она читает строки JSON, вызывает
  `slots.Available` и пишет ответ строкой JSON. Менять её не нужно;
- `Makefile` с целью `build`, которая собирает `bin/slots`;
- `testdata/slots/`: два образца случаев, `berlin-monday-morning.json` и `utc-two-windows.json`.

## Что сделать

1. Перенесите свои примеры из `docs/spec.md` в файлы `testdata/slots/<id>.json`, по одному
   объекту на файл. Добавьте случаи для решений, которые ещё никто не различает. В двух образцах
   стартера (`berlin-monday-morning.json` и `utc-two-windows.json`) поле `req` ссылается на
   REQ-01 и REQ-05 спецификации стартера; если `docs/spec.md` у вас свой, поправьте `req` под свою
   нумерацию: каждое требование из `req` должно быть в вашем `docs/spec.md`.
2. Напишите табличный тест на Go, который читает эти файлы и сравнивает `Available` с `expected`.
   Тест не оценивается: он для вашего цикла "красный, зелёный", и его читает ментор.
3. Реализуйте `slots.Available` в `backend/internal/slots` по требованиям REQ-01...REQ-10 (номера
   спецификации стартера, у вас они могут быть другими).

## Шов `bin/slots`

- `make -s build` оставляет исполняемый файл `bin/slots`. Это может быть любая программа (собранный
  Go, скрипт); символическая ссылка допускается, только если она указывает внутрь рабочей папки.
- Проверка запускает `bin/slots` один раз, в корне собранной копии, и пишет в его stdin строки, по
  одному объекту JSON на строку, потом закрывает stdin. Каждая строка это ровно объект `request` из
  формата случая (ниже): `{now, schedule, eventType, bookings, from, to}`.
- На каждую входную строку `bin/slots` печатает ровно одну непустую строку, в том же порядке.
  Пустые строки вывода не считаются. Строка ответа: `{"items": [{"start": ..., "end": ...}, ...]}`,
  у объекта ровно ключ `items`, у каждого элемента ровно `start` и `end`. `items` это массив: пустой
  ответ пишется `[]`, а `"items": null` отклоняется. JSON строгий: повторный ключ и `NaN`
  отклоняются. После конца ввода `bin/slots` выходит с кодом 0.
- Метки времени в ответе: любая дата-время RFC 3339 со смещением: `T` или `t`, `Z`, `z` или
  `±hh:mm`, дробная часть секунд любая, `-00:00` читается как UTC. Секунда 60 отклоняется. Ответ
  сравнивается как моменты, смещение в записи может быть любым.
- stderr не читается. Если что-то не так, сообщение показывает его последние 10 строк.

## Формат случая

Файл `testdata/slots/*.json` содержит один объект JSON `{id, req, request, expected}`. Это тот же
формат, что у блока `slots-example` в уроке 1, без обёртки в блок кода. Все ключи обязательны,
других ключей быть не может.

- JSON строгий: повторный ключ, `NaN`, `Infinity` и числа вне диапазона отклоняются. Файл в UTF-8,
  не больше 64 КБ, файлов не больше 60.
- `id`: от 1 до 64 символов из `A-Z a-z 0-9 _ -`, не повторяется между файлами.
- `req`: непустой список строк `"REQ-NN"`, каждое требование есть в `docs/spec.md`.
- `request`: объект `{now, schedule, eventType, bookings, from, to}`.
  - `now`, `from`, `to`: метка RFC 3339 с заглавной `T`, с секундами и со смещением `Z` или
    `+hh:mm`/`-hh:mm`; дробная часть секунд допускается. Не принимаются время без смещения, строчные
    `t` и `z`, смещение `-00:00`. `to` позже `from`, и между ними не больше 14 суток.
  - `schedule`: `{name, timeZone, weekly, overrides}`. `name` от 1 до 120 символов. `timeZone` один
    из поясов Europe/Berlin, America/New_York, America/Los_Angeles, Australia/Sydney, Asia/Kolkata,
    Asia/Kathmandu, Europe/Moscow, UTC. `weekly` это список `{weekday, start, end}`, `weekday` от 1
    до 7 (понедельник = 1). `overrides` это список `{date, intervals}`, `date` вида `YYYY-MM-DD`,
    одна запись на дату, `intervals` это список `{start, end}` (может быть пустым). Время `HH:MM` от
    00:00 до 23:59, `24:00` только как конец; начало раньше конца; интервалы одного дня недели или
    одного исключения не пересекаются, касаться могут.
  - `eventType`: `{title, durationMinutes, slotIncrementMinutes, bufferBeforeMinutes,
    bufferAfterMinutes, minimumNoticeMinutes, bookingWindowDays}`. `title` от 1 до 120 символов.
    Числа только целые (`true`, `false` и `30.0` отклоняются): `durationMinutes` 5-480,
    `slotIncrementMinutes` 5-240, буферы 0-240, `minimumNoticeMinutes` 0-43200,
    `bookingWindowDays` 1-365.
  - `bookings`: не больше 30 объектов `{start, end, bufferBeforeMinutes, bufferAfterMinutes,
    status}`, `end` позже `start`, буферы 0-240 (это буферы вида встречи бронирования), `status`
    это `"confirmed"` или `"cancelled"`.
- `expected`: список `{start, end}` из меток RFC 3339, по порядку начала.

Если файл не читается, сообщение называет файл, `id` и путь к полю, например
`request.schedule.weekly[2].end`.

## Рекомендация для урока 7

В уроке 7 ваши случаи будут прогоняться через HTTP: тестовый стенд создаст расписание, виды встреч и
бронирования через `POST` и сравнит `GET` слотов с `expected`. Чтобы случай можно было так
повторить, пишите его по этой рекомендации. Это рекомендация, а не правило проверки: проверка
`slot-cases-kill-mutants` засчитывает любой случай, который совпадает с моделью.

- `request.now = "2026-03-01T08:00:00Z"`. Это значение урок 7 передаёт серверу как `CALENDAR_NOW`.
  Все переводы часов 2026 года в восьми поясах лежат в пределах 365 суток от него, так что у
  каждого решения есть достижимая дата.
- Каждое бронирование это слот, который можно забронировать при этом `now`, в порядке списка: он на
  сетке своего вида встречи, внутри доступности, не раньше уведомления, внутри окна бронирования и
  не пересекается с более ранними подтверждёнными бронированиями списка. Длительность бронирования
  в целых минутах, от 5 до 480.
  - Вид встречи бронирования это `eventType` случая, если длительность и буферы бронирования
    совпадают с его. Иначе это второй вид встречи на том же расписании: с длительностью и буферами
    бронирования и с шагом, уведомлением и окном бронирования из `eventType` случая. Его создаст
    стенд урока 7.
  - Отменённое бронирование создаётся и сразу отменяется.
- У каждого случая свои даты (или стенд урока 7 отменяет бронирования случая после него). Иначе
  бронирования одного случая помешают другому: бронирования конфликтуют для всех видов встреч хоста.

## Готово, когда

### Проверка `slots-accepted`

1. `make -s build` в свежей копии рабочей папки завершается с кодом 0 за 180 секунд и оставляет
   исполняемый `bin/slots`.
2. `bin/slots` отвечает на 160 проб за 60 секунд по правилам шва выше, выводит не больше 4 МиБ и
   выходит с кодом 0.
3. Каждый ответ равен списку слотов модели заказчицы: моменты, по порядку, одно начало один раз,
   по возрастанию начала, начала в `[from, to)`, по правилам из `docs/spec.md`.

Пробы новые при каждом запуске: 16 групп по 10 признаков.

- Группы: Europe/Berlin, America/New_York, America/Los_Angeles и Australia/Sydney, каждый в день
  перехода на летнее время, в день перехода на зимнее время и в обычный день; Asia/Kolkata,
  Asia/Kathmandu, Europe/Moscow и UTC в обычный день. Дни перевода настоящие, 2026-2028 годов, и
  одна граница окна попадает в несуществующий или повторяющийся час.
- Признаки: недельное правило с шагом, равным длительности; шаг не равен длительности, окно
  начинается не в начале часа; исключение даты со своими окнами; исключение даты как выходной;
  бронирования и буферы (в том числе касание); отменённое бронирование; минимальное уведомление;
  окно бронирования; окна до 24:00 и с 00:00 на несколько дней; несколько окон и дней недели.
- `now` у каждой пробы свой: за 1-20 дней до даты, или его задаёт признак уведомления или окна.
  Ответ модели на пробу не пустой.
- Метки в пробах: RFC 3339 с заглавной `T`, с секундами, `Z` или `±hh:mm`, без дробной части.
  Кроме `Z` и смещения самого пояса встречаются +05:45, +05:30, -03:30, +10:00 и -08:00.

### Проверка `slot-cases-kill-mutants`

Ваш код здесь не запускается: проверка читает случаи как данные.

4. В `testdata/slots/` есть хотя бы один файл `*.json`, и каждый читается по формату выше.
   Читаются только обычные файлы `*.json` прямо в этом каталоге; подкаталоги и другие файлы не
   читаются, файл `*.json`, который является символической ссылкой, это ошибка.
5. Для каждого случая список модели равен `expected` поэлементно, по порядку, как моменты.
6. Каждое из двенадцати неправильных решений о времени даёт на хотя бы одном случае, совпавшем с
   моделью, другой список, чем модель. Случай, который с моделью расходится, для этого пункта не
   считается. Двенадцать неправильных решений:
   - восемь из урока 1: **разрыв** (несуществующее местное время читается по смещению после
     перевода); **повтор** (берётся второй из двух моментов); **смежность** (касающиеся интервалы
     считаются пересекающимися); **буферы с одной стороны** (собственные буферы нового слота не
     учитываются); **уведомление от начала дня** (отсчёт от местной полуночи дня `now`);
     **окно на день длиннее** (`bookingWindowDays + 1`); **исключение добавляется** (окна исключения
     добавляются к недельным); **день недели в UTC** (по дате в UTC момента местной полуночи);
   - **шаг дня 24 часа**: следующий день получается прибавлением 24 часов, а не по календарной дате;
   - **последний слот отброшен**: слот, который кончается ровно в конце окна, не предлагается;
   - **отменённое занимает**: отменённое бронирование блокирует время, как подтверждённое;
   - **шаг от начала часа**: кандидаты отсчитываются от начала часа, а не от начала окна.

Не проверяются: рекомендация для урока 7 (о ней только строки "к сведению", ниже), правило "свои
даты", ваш тест на Go.

## Окружение проверки

Проверка один раз снимает копию рабочей папки: только обычные файлы, `.git` входит, `__pycache__`
нет, символические ссылки только если ведут внутрь. В свежей копии она запускает `make -s build`, а
потом `bin/slots`. У `make`, у всего, что он запускает, и у `bin/slots` ровно такое окружение:

- `PATH=/opt/academy/bin:/opt/node/bin:/usr/local/go/bin:/usr/bin:/bin`;
- свои пустые `HOME`, `TMPDIR`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`;
- `NUXT_TELEMETRY_DISABLED=1`;
- случайный `TZ` из Europe/Berlin, America/New_York, America/Los_Angeles, Australia/Sydney,
  Asia/Kolkata, Asia/Kathmandu, Europe/Moscow (никогда не UTC);
- `GOENV=off GOFLAGS= GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off GOWORK=off CGO_ENABLED=0 GOEXPERIMENT=`,
  свои `GOTMPDIR`, `GOPATH`, `GOMODCACHE` и один `GOCACHE` на запуск проверки;
- больше ничего.

Что из этого следует:

- сети при сборке нет, поэтому сторонние модули Go должны лежать в `vendor/` в рабочей папке
  (`go mod vendor`);
- строка `go` в `go.mod` не выше версии Go в образе (1.27.x);
- `go.work` не используется;
- `TZ` процесса не совпадает с поясом расписания: движок не должен зависеть от `time.Local`.

Вердикт берётся только из ответов `bin/slots` и сравнения с моделью заказчицы. Вывод ваших тестов,
`go test`, `go vet` и `make` не читается.

## Как проверяется

- **`slots-accepted`** (команда в рабочей папке, 300 с): пункты 1-3. Сообщения:
  - сборка: "make -s build не уложился в 180 с", "make -s build завершился с кодом N" (с последними
    40 строками вывода), "после make -s build нет исполняемого файла bin/slots";
  - шов: "bin/slots не ответил на 160 проб за 60 с", "bin/slots вывел больше 4 МиБ", "bin/slots
    вывел N строк ответа на 160 строк запроса", "bin/slots ответил верно, но завершился с кодом N";
  - первое расхождение: группа и признак пробы, `TZ` процесса, строка запроса как она отправлена,
    список модели и ваш список в поясе расписания (не больше 12 слотов), или причина, почему строка
    ответа не читается (например "bin/slots ответил ошибкой: ...", "items должен быть массивом").
    Затем строка "расхождения есть в: ..." с поясами и видами дня. Пробы при каждом запуске новые,
    поэтому подгонка под одну пробу не поможет.
- **`slot-cases-kill-mutants`** (команда в рабочей папке, 60 с): пункты 4-6. Сообщения:
  - ошибки формата называют файл, `id` и поле;
  - для первого случая, который расходится с моделью, список модели и ваш список; для остальных
    только файл и `id`;
  - на каждое неразличённое решение строка "ни один случай, совпадающий с моделью, не различает
    решение: ..." с названием решения и номером требования в спецификации стартера;
  - последняя строка при провале "различено решений: K из 12".
  - Строки "к сведению" проверку не проваливают: случай с другим `now` или с бронированием, которое
    нельзя создать через `POST /bookings` при `now` из рекомендации в порядке списка. Такой случай в
    уроке 7 пройдёт только через `bin/slots`, не через HTTP.
- Сообщение, которое начинается с "ошибка проверки, не ваша", значит, что сломалось окружение
  проверки (инструмент не найден в `PATH` проверки, не хватает места, база поясов в образе
  расходится с ожидаемой), а не ваша работа.

Число попыток не ограничено.

## Как работать (совет, не проверяется)

- Начните с файлов случаев: примеры из `docs/spec.md` копируются почти без правок. Запустите
  `slot-cases-kill-mutants` и добавьте случаи на решения из сообщения.
- Тест держите рядом с пакетом (`backend/internal/slots/slots_test.go`), сравнивайте слоты через
  `Equal`, а не `==`. Запуск из `backend/`: `go test ./...`.
- Шов можно попробовать руками: `make -s build`, потом
  `python3 -c 'import json,sys; print(json.dumps(json.load(open(sys.argv[1]))["request"]))' testdata/slots/berlin-monday-morning.json | bin/slots`.
- Поставьте у себя `TZ=America/New_York` или `TZ=Australia/Sydney` при запуске теста: так
  зависимость от `time.Local` видна сразу.
