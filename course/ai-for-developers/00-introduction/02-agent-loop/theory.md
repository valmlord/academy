# Устройство агента: цикл, харнесс, инструменты, MCP

## Проблема

Агент "сам" прочитал файл и запустил тесты. Кто на самом деле исполнил команду, кто решил, что ей
можно, и откуда модель узнала результат?

Модель не умеет читать файлы и запускать процессы. Она умеет только выдавать текст. Всё остальное
делает программа вокруг неё, и если вы не знаете, где проходит граница, вы не поймёте ни цену
сессии, ни то, почему агент "забыл" правило, ни где ставить защиту.

## Идея: модель решает, харнесс делает

Документация Claude Code описывает цикл агента так: собрать контекст, выполнить действие, проверить
результат, повторить. Пользователь может прервать цикл в любой момент.

Внутри одного шага роли разделены жёстко:

1. **Модель выбирает**: в ответе она пишет вызов инструмента (имя и аргументы) или финальный ответ.
2. **Харнесс проверяет разрешение**: можно ли этот инструмент с этими аргументами.
3. **Харнесс исполняет** инструмент, если можно, и получает результат.
4. **Харнесс возвращает результат в контекст** и снова вызывает модель.

Claude Code называет себя "the layer around the model that provides the tools and manages the
context the model sees": это и есть харнесс. Проверка разрешений стоит в харнессе и происходит до
запуска инструмента. Поэтому в уроке про безопасность мы будем настраивать именно харнесс, а не
уговаривать модель.

## Контекст и ход

**Контекст** это список сообщений, который харнесс отправляет модели. **Ход** это один запрос к
модели, и в нём уходит весь этот список целиком. Модель ничего не помнит между ходами: она видит
только то, что харнесс положил в запрос.

Пример. После двух ходов список выглядит примерно так:

```json
[
  {"role": "user", "text": "Почини падающий тест"},
  {"type": "tool_call", "id": "c1", "name": "run_tests", "arguments": {}},
  {"type": "tool_result", "id": "c1", "content": "FAILED test_total: 9 != 10"},
  {"type": "tool_call", "id": "c2", "name": "read_file", "arguments": {"path": "src/total.py"}},
  {"type": "tool_result", "id": "c2", "content": "def total(items): ..."}
]
```

Третий ход отправит модели все пять сообщений. Отсюда три следствия, на которых стоят следующие
уроки:

- **длинная сессия дорожает**: каждый ход заново несёт всю историю (урок про экономику);
- **определения инструментов тоже лежат в контексте** и едут в каждом ходе. Много подключённых
  инструментов значит много токенов на каждом шаге. Каждый подключённый MCP-сервер добавляет свой
  список инструментов. Claude Code по умолчанию откладывает их определения: в контекст сразу идут
  имена инструментов и инструкции сервера, а полные определения подгружаются по требованию
  (подробнее в уроке про контекст). Документация Claude Code отмечает, что CLI, который агент и так
  знает (например `gh`), часто обходится по контексту дешевле MCP-сервера;
- **субагент** это отдельный цикл со своим контекстом. Он может прочитать сто файлов, а родителю
  вернёт только короткую сводку. Его вызовы инструментов в контекст родителя не попадают.

## Workflow или агент

Статья Anthropic "Building effective agents" (2024-12-19) различает два вида систем. **Workflow**
ведёт модель по заранее заданному пути в коде. **Агент** сам решает, какой инструмент вызвать
следующим, и получает обратную связь от среды в цикле. Агент гибче, но дороже и менее предсказуем.
Конкретные шаблоны workflow разберём в модулях 02 и 03.

Оттуда же идея ACI (agent-computer interface): описания и параметры инструментов заслуживают такой
же заботы, как интерфейс для человека. И poka-yoke: проектируйте инструмент так, чтобы ошибиться было
трудно, например требуйте абсолютные пути вместо относительных.

## Куда подключаются расширения

В Claude Code поверх базового цикла подключаются MCP-серверы (внешние инструменты), хуки (код,
который харнесс запускает на событиях, например перед вызовом инструмента) и субагенты. Skills
разберём в модуле 01. Сама схема "модель выбирает инструмент, программа вокруг исполняет и
возвращает результат" не особенность Claude Code: это общее определение агента из статьи Anthropic
выше (модель сама направляет использование инструментов в цикле).

Чекпоинты Claude Code откатывают только правки файлов. Действия во внешних системах (база данных,
API, деплой) откатить нельзя.

## MCP: протокол для внешних инструментов

Model Context Protocol описывает, как харнесс получает инструменты из другого процесса.

- **Роли**: **host** это приложение с моделью (например Claude Code), **client** живёт внутри host и
  держит соединение с одним сервером, **server** предоставляет возможности.
- **Что даёт сервер**: tools (инструменты), resources (данные), prompts (шаблоны).
- **Формат**: JSON-RPC 2.0. Клиент узнаёт инструменты через `tools/list` и вызывает через
  `tools/call`.
- **Транспорты**: stdio (host запускает сервер как дочерний процесс и пишет в его stdin) для
  локальных серверов и Streamable HTTP для удалённых.

Обмен в упрощённом виде:

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/list"}
{"jsonrpc": "2.0", "id": 1, "result": {"tools": [{"name": "word_count", "inputSchema": {"type": "object"}}]}}
{"jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": {"name": "word_count", "arguments": {"text": "a b"}}}
{"jsonrpc": "2.0", "id": 2, "result": {"content": [{"type": "text", "text": "2"}]}}
```

Заметьте: к серверу подключается харнесс, а не модель. Модель видит только определения инструментов
в контексте и пишет вызов; запрос `tools/call` отправляет клиент.

**Риск**: локальный MCP-сервер это произвольный код, который работает с правами клиента, то есть с
вашими. А описания инструментов от сервера это недоверенный ввод: в них может быть инструкция для
модели. Ставьте серверы из проверенных источников и смотрите, какую команду они запускают.

Датированная оговорка: ревизия спецификации 2026-07-28 сделала протокол stateless и убрала
рукопожатие `initialize`. Спецификация меняется быстро, перед работой с настоящим сервером сверяйтесь
с актуальной версией.

## Частые ошибки

- Не возвращать результат инструмента в контекст: модель вызывает тот же инструмент снова и снова.
- Нет ограничения на число ходов: цикл с моделью, которая не пишет финальный ответ, крутится вечно.
- Сначала исполнить, потом спросить разрешение. Проверка имеет смысл только до запуска.
- Падать на неизвестном имени инструмента. Правильно вернуть модели ошибку как результат: она
  исправится на следующем ходе.
- Хардкодить список удалённых инструментов вместо `tools/list`.

## Что делать в практике

Вы напишете функцию `run_agent` в `harness.py`: цикл, который вызывает модель, проверяет
разрешение, исполняет локальные инструменты или инструменты внешнего процесса через MCP-образный
протокол и возвращает результаты в контекст. Протокол в практике упрощённый и не соответствует
спецификации: в нём нет `_meta`, `resultType`, `server/discover`, `ttlMs` и `cacheScope`.
