# Задание: запреты, которые исполняет харнесс

Время: около 80 минут (около 50 из них практика).

## Что в рабочей папке

Репозиторий `invoice-service` и в нём:

- `.claude/settings.json` с ошибками в правилах разрешений;
- `CLAUDE.md` со строкой "NEVER read .env";
- `Makefile` с целью `agent`, которую README описывает как "как мы запускаем агента на ноутбуках";
- `.claude/hooks/protect_generated.py`: заготовка хука (shebang `#!/usr/bin/env python3`, бит
  исполнения стоит, читает stdin, дальше TODO).

## Политика

1. Агент может править всё в `src/**`, кроме `src/invoices/generated/**`. Запрет исполняет
   deny-правило; хук дополнительно блокирует правку и объясняет "regenerate with make codegen".
2. Никогда не читать и не править ни один файл `.env*` на любой глубине.
3. `make test` и `make lint` выполняются без вопроса.
4. `git status` и `git diff` выполняются без вопроса (подумайте, нужно ли для этого правило).
5. `git push` запрещён.
6. Каждая загрузка из веба спрашивает, включая домены документации. Принятая форма:
   `"ask": ["WebFetch(domain:*)"]`. Голый `WebFetch` в ask здесь не принимается: как он соотносится
   со встроенным списком доверенных доменов документации, не документировано.
7. Никакого обхода разрешений на хосте.

## Шаги

1. Исправьте `.claude/settings.json` под пункты 1-6. Allow-правила берите только из закрытого
   набора, а `defaultMode` приведите к правилу о режиме (оба правила в разделе
   `permissions-policy` ниже). Уберите `"defaultMode": "bypassPermissions"`: Claude Code 2.1.311
   игнорирует его в проектных настройках, но строка вводит читателя в заблуждение.
2. Уберите обход разрешений из `Makefile`: либо удалите цель `agent`, либо оставьте в ней вызов
   `claude` без флагов, меняющих разрешения (точное правило в справке ниже). Остальной `Makefile`
   не меняйте. Какие ещё файлы можно менять, сказано в "Справка: Makefile и другие файлы".
3. Допишите `.claude/hooks/protect_generated.py`. Хук это **один файл, только стандартная
   библиотека Python**. Он должен:
   - блокировать Edit и Write в `src/invoices/generated/` проекта: exit 2 и `make codegen` в stderr
     (или exit 0 с JSON `permissionDecision: "deny"` и `make codegen` в причине);
   - пропускать (exit 0 без deny) всё остальное, включая похожие имена вне этого каталога;
   - блокировать, если stdin не JSON или в нём нет `tool_input.file_path`: exit 2, или любой
     ненулевой код, если в регистрации стоит `"onFailure": "block"`. Exit 1 без него это fail open.
4. Зарегистрируйте хук в `.claude/settings.json`: одна группа `PreToolUse` с matcher `"Edit|Write"`
   и одним объектом хука. Других хуков в `.claude/settings.json` и `.claude/settings.local.json` быть
   не должно. Минимальный объект хука:

   ```json
   {
     "type": "command",
     "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_generated.py",
     "args": []
   }
   ```

   Другие допустимые формы и ключи собраны в справке ниже.

Файлы настроек должны оставаться строгим JSON: `NaN`, `Infinity` и `-Infinity` это ошибка формата.

## Что значит "готово"

Обе командные проверки и квиз пройдены.

## Как проверяется

**`permissions-policy`** (команда в рабочей папке). Ваш `.claude/settings.json` прогоняется через
модель семантики Claude Code 2.1.311: интерактивная сессия в доверенной папке, режим неизвестен.
Исход каждой пробы: `deny`, `ask`, `allow`, `builtin` (встроенный набор только для чтения или чтение
в рабочей папке) или `mode-dependent` (ни одно правило не совпало).

- Чтение `.env`, `.env.staging`, `config/.env`; правка `.env`; запись `config/.env.local`: `deny`.
- Правка и запись в `src/invoices/generated/` (имена файлов случайные): `deny`.
- Правка `src/invoices/api.py` и других файлов в `src/`, создание нового файла в новом каталоге
  `src/`, правка `src/invoices/generated_report.py`: `allow`.
- Чтение файлов `src/`, включая `generated/`: `builtin` или `allow`, но не `deny` и не `ask`.
- `make test`, `make lint`: `allow`. `git status`, `git diff`: `builtin` или `allow`.
- `git push` в нескольких формах, в том числе внутри составной команды: `deny`.
- `make db-reset`, `git -C . push origin main`, `git -c ... diff`, `curl` на внешний адрес: не `allow`.
- Команды через интерпретатор (`sh -c`, `bash -c`, `python3 -c`, `env …`): не `allow`.
- WebFetch на случайный домен и на домен документации: `ask`.
- Закрытый набор allow-правил. Разрешены только:
  - `Edit(...)` внутри `src/`: путь `src/...`, `./src/...` или `/src/...`, никогда `//`, `~/` или
    `..`;
  - `Bash(make test)` и `Bash(make lint)`;
  - по желанию точные `Bash(git status)` и `Bash(git diff)`.

  Любое другое allow-правило даёт провал с сообщением "allow-правило вне разрешённого набора:
  <правило>", в том числе шаблоны вроде `Bash(git diff *)` или `Bash(make test *)`, allow для
  `Read(...)`, allow для WebFetch и голые имена инструментов. Причина: широкий allow (интерпретатор,
  запускатель пакетов, `find`, `docker`) выполняет что угодно без запроса. Правила deny и ask этот
  набор не ограничивает.
- Режим: `permissions.defaultMode` отсутствует, равен `"default"`, `"manual"` или `"plan"`
  (`manual` это документированный синоним `default`). Любое другое значение даёт провал:
  - `acceptEdits`: правки вне `src/` и команды `rm`, `mv`, `cp` в рабочей папке пройдут без запроса;
  - `dontAsk`: всё, что должно спрашивать, превращается в отказ, и пункт 6 политики (каждая загрузка
    спрашивает) ломается;
  - `bypassPermissions`: из проектных настроек Claude Code его игнорирует, строка только вводит в
    заблуждение;
  - `auto`: из проектных настроек тоже не действует (сессия начинает во встроенном стартовом
    режиме), строка вводит в заблуждение.

  Любые другие значения вне упражнения.
- Объект `permissions` содержит только `allow`, `ask`, `deny`, `defaultMode` и, по желанию,
  `disableBypassPermissionsMode` (значение `"disable"`). Любой другой ключ даёт провал. Пример: `additionalDirectories`
  открывает агенту файлы вне проекта без запроса, и это ломает пункт 7 политики.
- Статические проверки: `Makefile` соответствует правилу из справки ниже; хуки
  соответствуют правилу "ровно один хук" из справки ниже (это правило проверяют обе командные
  проверки).
- Проверка понимает правила только для инструментов `Bash`, `Read`, `Edit`, `Write`, `MultiEdit`,
  `NotebookEdit`, `Glob` и `WebFetch`. Понимает не значит "работает": правила с путём для `Write`,
  `MultiEdit`, `NotebookEdit` и `Glob` Claude Code принимает, но они никогда не совпадают, и проверка
  помечает их как "принятые Claude Code, но никогда не совпадающие". Для защиты файлов пишите
  `Edit(...)`.
- Всё остальное даёт ошибку "unsupported rule form": другие инструменты, правила с `!`, формы полей
  (`Bash(command:...)`), обёртки.

Сообщения называют категорию пробы и проблему формы правила, но не правильный текст правила.

**`hook-blocks-generated`** (команда в рабочей папке):

- (а) регистрация: ровно один хук; matcher из принятого списка; объект хука в одной из принятых
  форм; только разрешённые ключи; хуки не выключены (всё это в справке ниже);
- (б) поведение: проверка запускает файл хука как `python3 -I <hook>` (каталог скрипта не на
  `sys.path`, поэтому соседние модули и сторонние пакеты не импортируются) со свежим окружением, где
  `CLAUDE_PROJECT_DIR` и `cwd` в JSON указывают на случайный временный каталог проекта. На вход идут
  JSON-сообщения Edit и Write в формате документации: правки в `generated/` (в том числе через `..`)
  должны блокироваться, похожие пути вне него (`generated_report.py`, `generated_helpers.py`,
  `docs/generated-notes.md`, `tests/generated/`, `generated/../api.py`) пропускаться, а не-JSON и
  JSON без `tool_input.file_path` блокироваться. Read на вход не подаётся.

**`security-quiz`** (квиз): 6 вопросов-сценариев, нужно 5 верных. В вопросах с пометкой "выберите
все верные" засчитывается только точный набор ответов.

## Справка: регистрация хука

### Ровно один хук

`.claude/settings.json` и `.claude/settings.local.json` вместе содержат ровно один хук: одну группу
`PreToolUse` с одним объектом хука, регистрацию `protect_generated.py`. Любое другое событие
(например `PermissionRequest`), вторая группа или второй объект хука дают провал: такой хук мог бы
ответить "allow" и пропустить запросы разрешений мимо политики.

### Matcher

Принимается простой список имён инструментов через `|` или `,` (пробелы вокруг разделителя
допустимы). В нём должны быть `Edit` и `Write`, кроме них можно `MultiEdit` и `NotebookEdit`.
Примеры: `Edit|Write`, `Write|Edit`, `Edit | Write`, `Edit, Write`, `Edit|Write|MultiEdit`,
`Edit|Write|NotebookEdit`.

Отклоняются:

- регулярные выражения: matcher с другими символами, кроме букв, цифр, `_`, `-`, пробелов, `,` и
  `|`, Claude Code вычисляет как регулярное выражение JavaScript без якорей, и
  `Edit.*` совпадает не с тем, что кажется (не с `Write`, зато с `NotebookEdit`);
- пробел без разделителя (`Edit Write`): это одно имя, которое ни с чем не совпадает;
- `*`, пустой или отсутствующий matcher;
- любое другое имя, включая `Read`: политика разрешает читать `generated/`.

### Принятые формы объекта хука

`P` ниже это `/.claude/hooks/protect_generated.py`.

Exec form (`args` есть, оболочки нет; `command` и `args` сравниваются точно, без обрезки пробелов):

- E1: `"command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_generated.py", "args": []`
- E2: `"command": "python3", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_generated.py"]`
- E3: `"command": "python3", "args": ["-I", "${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_generated.py"]`

Shell form (`args` нет): `command` после обрезки пробелов, табов и переводов строки по краям ровно
одна из строк ниже, с необязательным префиксом `python3 ` или `python3 -I ` (всего 12 вариантов):

- `"$CLAUDE_PROJECT_DIR"/.claude/hooks/protect_generated.py`
- `"${CLAUDE_PROJECT_DIR}"/.claude/hooks/protect_generated.py`
- `"$CLAUDE_PROJECT_DIR/.claude/hooks/protect_generated.py"`
- `"${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_generated.py"`

Почему кавычки: оболочка делит незакавыченный путь с пробелом на два аргумента, и хук не стартует.

Если интерпретатор не назван (E1 и shell form без `python3`), файл хука должен начинаться со строки
`#!`, которая называет python3, и иметь бит исполнения у владельца: иначе Claude Code не сможет его
запустить. Заготовка уже такая.

### Отклоняемые формы

- Строка shell form с кавычками при наличии `args` (даже `args: []`): в exec form нет оболочки,
  кавычки и `$` уходят в запуск буквально, хук не стартует, а не стартовавший хук это fail open.
- Незакавыченный `$CLAUDE_PROJECT_DIR/...`: в shell form ломается на пробеле, в exec form голый
  `$VAR` не подставляется.
- Относительные пути `./.claude/...` и `.claude/...` (с `python3` или без): хук запускается в текущем
  каталоге Claude, а его сдвигают `cd` и worktree.
- `"command": "python3 script.py"` вместе с `args`: exec form запускает `command` как одно имя
  программы.
- Команда, которая только упоминает путь (`true .claude/hooks/protect_generated.py`): хук не
  выполняется.
- Невидимые символы по краям, которые оболочка не пропускает (неразрывный пробел, VT, CR): строка
  не совпадёт с формой.

### Ключи объекта хука

Разрешены: `type` (`"command"`), `command`, `args` (только как в E1-E3), `timeout` (нет или число не
меньше 5), `onFailure` (`"continue"` или `"block"`), `statusMessage` (строка). Любой другой ключ
отклоняется с его именем в сообщении:

- `if`: команда хука запускается только при совпадении шаблона, и опечатка в нём молча выключает хук.
  Хук сам решает по пути, `if` не нужен.
- `async`, `asyncRewake`: фоновый хук не блокирует вызов.
- `timeout` меньше 5 или не число: хук может не успеть, а таймаут без `onFailure: "block"` не
  блокирует. 5 секунд это порог упражнения, не лимит Claude Code (по документации по умолчанию 600 с).
- `shell`: вне упражнения (принятые строки проверены для оболочки по умолчанию; это не отказ Claude
  Code).
- `once` и любые другие ключи: вне упражнения.

## Справка: Makefile и другие файлы

`Makefile` сравнивается с исходным. Всё, кроме цели `agent`, должно остаться прежним; комментарии,
пустые строки и лишние пробелы не учитываются, а `agent` можно убрать из `.PHONY`.

Цель `agent` либо удалена, либо не имеет зависимостей и состоит ровно из одной строки рецепта:
`claude`, `claude --permission-mode default`, `claude --permission-mode manual` или
`claude --permission-mode plan` (можно с `@` в начале).

Менять можно только `.claude/settings.json`, `.claude/settings.local.json`,
`.claude/hooks/protect_generated.py` и цель `agent` в `Makefile`. Любой новый или изменённый скрипт
или исполняемый файл даёт провал: файл с расширением `.sh`, `.bash`, `.zsh`, `.py`, `.pl`, `.rb`,
`.js`, `.mjs`, `.cjs`, `.ts`, `.mk` или `.command`, файл с битом исполнения или файл, первая строка
которого начинается с `#!`. Исключение только файл хука. Другие файлы, например README, править
можно.

## Справка: выключатель хуков

Проверка не проходит, если `.claude/settings.json` или `.claude/settings.local.json` содержит
`disableAllHooks` с любым значением, кроме `false`: этот ключ выключает все хуки, не удаляя их.

## Попытки и подсказки

- Командные проверки: число попыток не ограничено; после 5 неудачных интерфейс предложит ментора.
- Квиз: не больше 3 попыток. После неудачи показывается только общий балл. Ответы и пояснения
  открываются после прохождения или после 3-й неудачной попытки, и тогда квиз закрывается как "не
  пройдено" с разбором у ментора.
- Ментор между попытками задаёт вопросы и подсказывает направление. По квизу он не говорит, какой
  вопрос неверен, а уровни "скелет" и "скажи прямо" открываются после того, как квиз закрыт.
