# Ассистенты, тарифы и экономика цена/качество

## Проблема

Модель в 5 раз дешевле за токен, а задача на ней обошлась дороже. Как это посчитать заранее?

Цена за токен написана на странице вендора. Цена задачи нигде не написана: она зависит от того,
сколько ходов сделает агент, сколько контекста он таскает и сколько раз промахнётся мимо кэша.

## Идея: считаем по составляющим

Токен это единица счёта. Из прошлого урока: каждый ход заново отправляет модели весь контекст.
Значит, вход каждого следующего хода в длинной сессии больше предыдущего.

Один запрос состоит из трёх платных частей:

- **некэшированный вход** (`input_tokens`): по полной цене входа;
- **чтение из кэша** (`cache_read_input_tokens`): префикс, который уже был в прошлом запросе, по
  сниженной цене;
- **выход** (`output_tokens`): самая дорогая часть за токен.

Стоимость запроса = сумма по составляющим: токены x цена этой составляющей. Стоимость сессии = сумма
по запросам.

Скидки в снимке на 2026-10-27 (страница Models overview):

- чтение из кэша стоит 10% цены входа, у Opus 5.5 и Sonnet 5.5 5%, у Fable 5.1 2.5%;
- Batch API даёт 50%, но ответ приходит асинхронно, поэтому для интерактивного агента не подходит.

## Пример расчёта

Цены mid-уровня (Sonnet 5.5) на 2026-10-27: $2 за миллион входных токенов, $10 за миллион выходных,
чтение из кэша 5% от входа, то есть $0.10 за миллион.

Ход в середине сессии: 2 000 некэшированных токенов, 60 000 из кэша, 1 500 на выходе.

```text
вход:   2 000 x $2    / 1 000 000 = $0.004
кэш:   60 000 x $0.10 / 1 000 000 = $0.006
выход:  1 500 x $10   / 1 000 000 = $0.015
итого                              $0.025
```

Главная составляющая этого хода выход, хотя токенов в нём меньше всего.

Теперь тот же ход после долгой паузы. Кэш истёк, и все 62 000 токенов идут как некэшированный вход:
$0.124 + $0.015 = $0.139, в 5.5 раза дороже. Сколько живёт кэш, зависит от поверхности: в
документации Claude Code на 2026-10-27 это около часа на подписке и около пяти минут при оплате по API.

## Цена за токен не равна цене за задачу

Дешёвая модель может сделать больше ходов: чаще ошибаться, перечитывать файлы, переделывать. А каждый
ход несёт всю накопленную историю, так что входные токены растут быстрее, чем число ходов. Модель в 5
раз дешевле, которой понадобилось в 3 раза больше ходов с вдвое более длинным контекстом в среднем,
съест в 6 раз больше входных токенов и окажется дороже.

Субагенты тоже умножают траты: каждый крутит свой цикл со своим контекстом. Пять субагентов, каждый
из которых читает репозиторий, это пять отдельных чтений репозитория, а не одно.

Сравнивать модели надо по стоимости задачи: токены всех ходов x цены. Не по прайсу.

## Подписка или API

Тарифы Claude на 2026-10-27 (claude.com/pricing): Free $0 без Claude Code; Pro $20 в месяц ($17 при
оплате за год) с Claude Code; Max от $100 в месяц (в 5 или 20 раз больше лимитов Pro); есть Team и
Enterprise. Лимиты подписки скользящие, окно 5 часов плюс недельные лимиты, и они общие для чата,
десктопа и Claude Code. Длинная сессия в Claude Code съедает тот же лимит, что и чат.

API оплачивается по токенам без таких окон. Ориентир из документации Claude Code (на 2026-10-27): в
среднем около $13 на разработчика за активный день, у 90% пользователей меньше $30 в день.
Чтобы выбрать, сравните ожидаемый расход по API за месяц с ценой тарифа и спросите себя, упрётесь
ли вы в окна лимитов. Решает ваш реальный профиль использования, а не правило.

## Рычаги

Каждый рычаг бьёт по своей составляющей:

| Рычаг | Что уменьшает |
|---|---|
| `/clear` или новая сессия между задачами | накопленный контекст, который едет в каждом ходе (и кэшированный, и нет) |
| модель меньшего уровня | цену всех составляющих сразу, но может добавить ходов |
| ниже effort, короче ответы | выход |
| меньше постоянно загруженных определений инструментов (CLI вместо MCP) | вход каждого хода |
| не оставлять задачу в простое посреди работы | промахи кэша: полный вход после паузы |

Короткая постоянная память агента тоже экономит вход каждого хода; подробно в уроке про память.

Где смотреть в Claude Code 2.1.311: `/usage` показывает расход, `/context` показывает, что сейчас
занимает контекст.

## Частые ошибки

- Считать кэшированные токены по полной цене входа или бесплатными.
- Считать выход по цене входа.
- Сравнивать модели по цене за токен, не по цене задачи.
- Думать, что файлы на диске, которые агент не читал, что-то стоят. Платите только за то, что
  попало в запрос.
- Путать составляющую и причину. "Пауза" это причина, а составляющая, которая выросла, это
  некэшированный вход.

## Что делать в практике

Вы посчитаете стоимость трёх сессий по логам токенов и датированному снимку цен. Две из них решают
одну задачу: одна на frontier-уровне, другая на mid, который по снимку на 2026-10-27 в 5 раз
дешевле за токен. Вы найдёте ход с промахом кэша и главную составляющую каждой сессии и ответите,
какая сессия дешевле за задачу. Какой рычаг применить к каждой сессии, вы обсудите с ментором, а
квиз проверит рычаги на сценариях.
