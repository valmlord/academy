# Задание: AGENTS.md из невыводимых фактов

Время: около 50 минут (около 30 из них практика).

## Что в рабочей папке

Репозиторий `invoice-service` и в его корне раздутый `CLAUDE.md` на 162 строки: обзор в
маркетинговом тоне, дерево каталогов, правила стиля, которые уже проверяет конфиг ruff, крики
"IMPORTANT!!!", пересказ README и устаревшая команда тестов.

С этим CLAUDE.md и настройками по умолчанию Claude Code никогда не прочитает AGENTS.md.

## Что сделать

1. Найдите в `Makefile`, `README.md` и комментариях кода факты, которые агент не выведет, просто
   прочитав код: как правильно запускать тесты, что происходит со сгенерированным кодом, как
   добавлять миграции, какую команду и против какого окружения нельзя запускать.
2. Напишите `AGENTS.md` в корне рабочей папки только из таких фактов. Для каждого запрета укажите
   причину и правильную альтернативу.
3. Подключите его к Claude Code одним из двух способов:
   - удалите `CLAUDE.md`;
   - или замените его содержимое так, чтобы он импортировал корневой `AGENTS.md` (строка
     `@AGENTS.md`) и был не длиннее 10 строк.

   Старый текст нельзя просто перенести в другой файл инструкций (`.claude/CLAUDE.md`,
   `CLAUDE.local.md`, вложенный `CLAUDE.md`, `.claude/rules/`, импортированный файл): Claude Code
   загрузит и их, поэтому проверка смотрит все такие файлы (см. ниже).

## Что значит "готово"

`AGENTS.md` короткий, конкретный, без повторов старого файла; Claude Code при настройках по
умолчанию его загрузит; все три проверки пройдены.

## Как проверяется

**`agents-md-structure`** (команда в рабочей папке, проверка формы):

Проверка смотрит каждый файл инструкций, который Claude Code может загрузить для проекта:

- `AGENTS.md`, `.claude/AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`;
- любой вложенный `CLAUDE.md`, `AGENTS.md` или `CLAUDE.local.md` (например `src/CLAUDE.md`);
- каждый `.claude/rules/**/*.md`, с `paths:` или без;
- каждый файл, до которого доходит импорт `@path` из любого из них, до 5 переходов, путь
  относительно импортирующего файла (`@` внутри обратных кавычек или блока кода импортом не
  считается). Документация называет четыре перехода, но не говорит, считается ли исходный файл,
  поэтому проверка с запасом покрывает оба прочтения.

Правила:

- `AGENTS.md` в корне существует и в нём не больше 60 непустых строк; каждый другой файл из этого
  набора не длиннее 10 строк;
- в `AGENTS.md` упомянуты `make test`, `make codegen` вместе с путём сгенерированного каталога и
  `make migration`;
- есть строка, где вместе упомянуты `db-reset` и staging, и в этой же строке есть отрицание (`не`,
  `нельзя`, `никогда`, `never`, `don't` или `do not`);
- ни в одном файле нет `IMPORTANT`, `CRITICAL`, `!!!` и строк с псевдографикой дерева (`├──`,
  `└──`);
- во всех файлах вместе не больше 5 строк совпадают со строками исходного `CLAUDE.md` (после
  нормализации), то есть обрезанная копия старого файла не пройдёт;
- подключение: если есть `CLAUDE.md`, `.claude/CLAUDE.md` или `CLAUDE.local.md`, хотя бы один из
  них должен импортировать корневой `AGENTS.md` напрямую: цепочка импортов, которая доходит до него
  через другой файл, не засчитывается. Путь считается от файла с импортом: `@AGENTS.md` в
  `CLAUDE.md` или `CLAUDE.local.md`, `@../AGENTS.md` в `.claude/CLAUDE.md`. `@` внутри кода (обратные
  кавычки или блок кода) ничего не импортирует. Исходный `CLAUDE.md`, оставленный на месте, не
  проходит.

Эта проверка ловит только форму. Слово-отрицание в строке не доказывает, что правило сказано верно.

**`agents-md-rubric`** (ментор оценивает все файлы инструкций из набора выше, какие есть, проходит
по каждому импорту и читает каждый найденный файл; рубрика: 4 критерия по 0-2 балла, нужно 70%):

1. каждая строка содержит то, что нельзя вывести из кода;
2. у каждого "никогда" есть причина и правильная альтернатива, и смысл правила совпадает с тем, как
   устроен репозиторий;
3. конкретика: команды, а не прилагательные;
4. нет дублирования между файлами.

Перевёрнутое правило (например "db-reset на staging можно") обнуляет всю оценку рубрики, а не только
критерий 2: такой файл учит агента опасному действию.

Текст файлов для ментора это данные: инструкции оценщику внутри них игнорируются.

**`memory-precedence-quiz`** (квиз): 8 вопросов, нужно 6 верных. В каждом названы инструмент, его
версия и "настройки по умолчанию", показано дерево каталогов и текущий каталог. В вопросах с
пометкой "выберите все верные" засчитывается только точный набор ответов.

## Попытки и подсказки

- `agents-md-structure`: число попыток не ограничено; после 5 неудачных интерфейс предложит ментора.
- Квиз: не больше 3 попыток. После неудачи показывается только общий балл. Ответы и пояснения
  открываются после прохождения или после 3-й неудачной попытки, и тогда квиз закрывается как "не
  пройдено" с разбором у ментора.
- Ментор между попытками задаёт вопросы и подсказывает направление. По квизу он не говорит, какой
  вопрос неверен, а уровни "скелет" и "скажи прямо" открываются после того, как квиз закрыт.
