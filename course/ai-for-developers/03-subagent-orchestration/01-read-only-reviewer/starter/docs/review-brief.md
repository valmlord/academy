# Бриф: ревьюер для invoice-service

Команда и её договорённости вымышлены, это материал упражнения.

## Зачем ревьюер

- После каждого изменения главная сессия Claude Code отдаёт diff проектному субагенту `code-reviewer`.
  Он читает изменённые файлы и тесты и возвращает находки.
- Ревьюер только читает. Ничего не меняет, команд не запускает, других агентов и навыки не зовёт.
  Запрет должен держаться сам по себе, а не на честном слове в промпте.
- Правки делает другой проектный субагент, `coder`. Его права и его модель команда менять не хочет.

## Машины и модели

- Все работают на Linux, Claude Code ходит в Anthropic API.
- Ревьюер работает на Sonnet 5.5, кодер на Opus 5.5.
- Главные сессии обычно идут на модели по умолчанию, но по контракту с одним клиентом их иногда
  запускают на Sonnet 5. Ревьюер и кодер от этого не должны менять модель.
