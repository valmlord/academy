# Бриф: invoice-service в закрытом контуре банка

Банк и его инфраструктура вымышлены, это материал упражнения.

## Сеть

- Интернета нет. Прокси нет.
- Модель доступна только через внутренний шлюз `https://llm.corp.local`.
- Пакеты Python берутся только из зеркала uv `https://pypi.corp.local/simple`, порт 443.
- Командам Bash нужно зеркало, и больше ничего.

## Доверие и доступ

- Корневой CA банка лежит в файле `/etc/corp/ca-bundle.pem`. Его нет в системном хранилище
  сертификатов. Он подписывает и шлюз, и зеркало.
- В `/etc/corp` лежит только этот файл CA.
- Токены к шлюзу живут недолго. Выдаёт их только программа `/opt/corp/bin/llm-token`: она печатает
  свежий токен.

## Агент

- У агента нет веб-инструментов. Файловые инструменты и shell у него остаются.
- Необязательный трафик Claude Code выключен.
- Хуки в `.claude/settings.json` остаются как есть и остаются включёнными.

## Терминалы команды

- Команда ставит пакеты через `uv`, в том числе из своих терминалов и вне этого репозитория.
  Терминалы читают только банковский профиль `launcher.env`.
- Файлы настроек uv (`pyproject.toml`, `uv.toml` на уровне проекта, пользователя или системы) на
  машинах команды не учитываются. Настройки uv попадают туда только из `launcher.env`.
- Лаунчер и каждая login-оболочка читают `launcher.env` построчно как `KEY=VALUE`. Они не убирают
  `export`, кавычки и пробелы, а окончания строк CRLF принимают.

## Файлы этого репозитория

- `launcher.env`: банковский профиль.
- `.claude/settings.json`: настройки проекта Claude Code.
- `home/.claude/settings.json`: на машине команды это `~/.claude/settings.json`.
