# Закрытый контур

## Проблема

Банк: интернета нет, модель доступна только через внутренний шлюз. Что в этой настройке Claude Code
сломается первым, а что утечёт?

Обычно ломается не одно место. Агент шлёт запросы на публичный адрес и не достаёт до него. Токен
лежит в файле, который коммитят. `uv` идёт за пакетами наружу или не доверяет сертификату
внутреннего сервера. Опаснее всего значения, которые заданы, но не там: в файле, который не читается,
или ключом, у которого другой смысл.

Ниже всё про Claude Code 2.1.314 и сессию в терминале в доверенной папке.

## Идея: пять разных вещей

- **Шлюз (gateway)**: сервис банка между Claude Code и провайдером модели. Claude Code шлёт запросы
  на его адрес с ключом, который выдал банк; ключ провайдера остаётся на шлюзе.
- **Прокси**: узел, через который идёт весь исходящий трафик (`HTTPS_PROXY`). API модели он не
  знает, он пересылает соединения. В практике прокси нет.
- **Корневой сертификат (CA)**: файл, которым банк подписывает свои серверы. Инструмент, который ему
  не доверяет, рвёт TLS-соединение с ошибкой сертификата.
- **Зеркало (mirror)**: внутренний сервер пакетов вместо публичного PyPI.
- **Список разрешённых хостов (egress allowlist)**: куда вообще можно ходить. Остальное закрыто.

Схема контура в практике:

- ноутбук -> шлюз -> модель;
- ноутбук и команды агента в песочнице -> зеркало пакетов;
- больше никуда.

Главное правило: у каждого инструмента свой адрес и своя настройка доверия. Claude Code и uv разные
программы, настройка одной на другую не действует.

## Как это работает

### Какое значение действует

Переменную можно задать в оболочке или в блоке `env` файла настроек. Если она задана и там, и там, в
большинстве сессий действует значение из файла настроек. До фоновых сессий надёжно доходят только
настройки, экспорт в оболочке может не дойти. Между файлами порядок такой: `.claude/settings.local.json`
выше `.claude/settings.json`, тот выше `~/.claude/settings.json` (над всеми ещё managed settings и
`--settings`). Это действующее значение: первое, что задаёт ключ, сверху вниз.

Две оговорки. Desktop-приложение и self-hosted раннер строят своё окружение запуска, и для
переменных из него `env` из файлов игнорируется. А в интерактивной сессии проектные и локальные
настройки ждут доверия к папке: большинство их значений `env` применяется только после того, как вы
его приняли (сразу действуют лишь те, что Claude Code считает безопасными: выбор модели, таймауты,
переключатели функций), а `apiKeyHelper` оттуда до этого не запускается.

### Адрес шлюза и ключ

`ANTHROPIC_BASE_URL` это базовый адрес без `/v1`: документация проверяет соединение запросом на
`"$ANTHROPIC_BASE_URL/v1/messages"`, путь добавляется к базе.

Ключ не кладут в `.claude/settings.json`: по документации этот файл коммитят и раздают всем, кто
клонирует репозиторий. Если токен уже попал в репозиторий, удалить строку мало: он остаётся в истории
git, поэтому его отзывают у того, кто выдал. Статический ключ может лежать и в заголовке: строка
`Authorization: ...` или `x-api-key: ...` в `ANTHROPIC_CUSTOM_HEADERS` такой же токен в файле.
Короткоживущие токены берут через `apiKeyHelper`:
команду, которая печатает текущий ключ. Claude Code кэширует ответ (по умолчанию пять минут) и
запускает команду снова.

```json
{
  "apiKeyHelper": "/usr/local/bin/get-llm-token"
}
```

### Две семьи переменных-флагов

Обычная переменная "вкл/выкл" понимает `1`, `true`, `yes`, `on` и `0`, `false`, `no`, `off` в любом
регистре. Несколько переменных смотрят только на то, задано ли значение. Среди них
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`: любое непустое значение, включая `0` и `false`, выключает
необязательный трафик (автообновления, телеметрию, отчёты об ошибках и другое). Вернуть трафик можно,
только убрав переменную или задав пустое значение.

### Веб-инструменты

- Deny-правило с голым именем (`WebSearch`, `WebFetch`) убирает инструмент из контекста агента.
- Шаблон в позиции имени инструмента в deny должен совпасть с полным именем: `"*"` совпадает со
  всеми инструментами, включая Bash и файловые. Документация показывает в таких шаблонах только
  `*` (`"*"`, `"mcp__*"`); другие символы шаблонов вроде `?` или `[...]` в ней не описаны.
- `WebFetch(domain:*)` в deny инструмент оставляет: каждая загрузка отклоняется, а команды в
  песочнице не достают ни до одного хоста.
- `CLAUDE_CODE_DISABLE_WEB_FETCH=1` убирает только WebFetch, WebSearch остаётся.
- Deny из любого файла сильнее allow из любого другого.

### Песочница и её список хостов

Песочница закрывает только команды оболочки: Read, Edit, WebFetch и WebSearch подчиняются правилам
разрешений, а хуки работают вне песочницы. Список хостов песочницы это `allowedDomains` плюс домены
из allow-правил `WebFetch(domain:...)`. Список только заранее разрешает. Судьбу хоста не из списка
решает режим разрешений: в Manual и `acceptEdits` вы получаете запрос; в `auto` соединение
отклоняется, кроме случая, когда команда заранее назвала хост и классификатор одобрил этот список; в
`dontAsk` отклоняется; в `bypassPermissions` проходит без запроса.

Отказ во всех режимах дают два ключа. `strictAllowlist: true` работает из пользовательских, managed
настроек или `--settings` (с v2.1.219); в `.claude/settings.json` или `.claude/settings.local.json`
репозитория он ни на что не влияет. `allowManagedDomainsOnly` работает из managed settings. Если
`strictAllowlist` стоит у пользователя, Claude Code (с v2.1.285) игнорирует в настройках репозитория
`allowedDomains`, allow-правила `WebFetch(domain:...)` и порты прокси.

Есть и выход мимо песочницы целиком. Если команда упала в песочнице, Claude может повторить её с
параметром `dangerouslyDisableSandbox`, и повтор идёт уже без песочницы: в Manual и `acceptEdits`
после запроса "Bash command (unsandboxed)", в `bypassPermissions` без запроса. Документация описывает
отключение этого повтора как отдельный шаг: `"allowUnsandboxedCommands": false` в настройках
`sandbox`. Тогда параметр игнорируется, и пока песочница работает, команды Claude идут в ней (кроме
`excludedCommands`). `false` из пользовательских, managed настроек или `--settings` держится, даже
если проект ставит `true`. Команды из `sandbox.excludedCommands` идут вне песочницы, без
ограничений файлов и без сетевого прокси, и `false` на них не действует. Исключение: если `false`
задан в managed settings или через `--settings` (если managed settings не ставят `true`), песочница
становится обязательной по требованию администратора (admin-required), и Claude Code игнорирует
`excludedCommands` из файлов репозитория; записи из `~/.claude/settings.json` действуют и тогда. В контуре, где из песочницы нельзя выходить, этот список
должен оставаться пустым везде.

### uv: свой индекс и своё доверие

- `UV_DEFAULT_INDEX` заменяет индекс по умолчанию, публичный PyPI. `UV_INDEX_URL` его устаревший
  синоним.
- `UV_INDEX` только добавляет индексы, а индекс по умолчанию остаётся последним запасным.
  `UV_EXTRA_INDEX_URL` устаревший синоним `UV_INDEX`.
- `UV_FIND_LINKS` тоже источник пакетов: список дополнительных мест, где uv ищет пакеты, помимо
  индексов.
- `NODE_EXTRA_CA_CERTS` читает Claude Code, в списке переменных uv её нет. uv берёт CA из
  `SSL_CERT_FILE` (файл PEM) или `SSL_CERT_DIR` (каталог с файлами PEM). `UV_SYSTEM_CERTS` включает
  хранилище ОС: если CA банка там нет, это не поможет.

Прокси: Claude Code не поддерживает SOCKS-прокси, а для прокси с NTLM или Kerberos документация
советует шлюз.

## Слабая локальная модель: меняйте процесс

Naresh Jain провёл один эксперимент: Codex на низком effort, сервис на Java, по 10 прогонов. Фронтир
GPT-6 Sol прошёл приёмочные тесты 10 из 10 и без обвязки, и с ней (с ней дороже). Модель
подешевле, GPT-6 Luna, прошла 3 из 10 без обвязки и 10 из 10 с ней. Его совет: дешёвой модели
запускать проверки на всём протяжении работы, фронтиру хватает одной финальной. Локальные
open-weights модели он не проверял и оставил на будущее, так что перенос на них наша экстраполяция.

Что ещё меняется с локальной моделью:

- в исследовании Spracklen и соавторов open-source модели выдумывали пакеты заметно чаще
  коммерческих: проверка зависимостей (урок 3) и зеркало с одобренными пакетами нужнее;
- без веб-поиска агент не узнает, есть ли API в вашей версии библиотеки (GitChameleon показывает,
  что с версиями модели справляются плохо): закрепляйте версии и кладите документацию к ним в
  репозиторий;
- задачи мельче: чем короче шаг, тем раньше проверка ловит ошибку (это рассуждение, а не замер).

Длинные промпты и уговоры этого не заменяют.

## Частые ошибки

- `/v1` в конце `ANTHROPIC_BASE_URL`.
- Токен удалён из файла, но не отозван.
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=0` "чтобы включить обратно".
- Ключ в файле, из которого он не действует, или в файле, который перекрыт другим.
- Одна переменная доверия "для всех инструментов".
- Deny-шаблон, который заодно убирает Bash или Read.

## Что делать в практике

Вы получите бриф банка и настройки проекта, в которых нарушены его требования. По каждому требованию
вы найдёте файл и ключ, который его обеспечивает, выпишете действующее значение и исправите
расхождения. Эти настройки живые: не открывайте в папке практики обычную сессию Claude Code, в задании
сказано, как работать безопасно.

## Справка (читать по необходимости)

**Поддерживаемые маршруты.** Шлюз через `ANTHROPIC_BASE_URL`, Amazon Bedrock, Google Cloud's Agent
Platform, Microsoft Foundry, Claude Platform on AWS и endpoint Mantle в Bedrock. Провайдера включают
`CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`,
`CLAUDE_CODE_USE_ANTHROPIC_AWS`, `CLAUDE_CODE_USE_MANTLE`.

**Локальная open-weight модель за Claude Code.** Ollama, vLLM и llama.cpp в своей документации
показывают, как подключить Claude Code к локальному серверу (настройку разбирали в модуле 00, урок
1). Это не маршрут вендора: Anthropic "doesn't support routing Claude Code to non-Claude models
through any gateway".

**Закрепить шлюз политикой.** Managed-настройка `allowedProviders: ["customEndpoint"]` (с v2.1.285)
пускает сессию только на тот `ANTHROPIC_BASE_URL`, который задан в `env` тех же managed settings.

**Короткий системный промпт.** `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT` выбирает полный или короткий
системный промпт: без переменной Haiku 4.5, Sonnet 5, Opus 4.7 и более ранние модели этих семейств
получают полный, новые модели короткий. В 2.1.312 Bedrock, Vertex, Foundry и Mantle перевели на
короткий промпт для имён моделей, которых Claude Code не знает. Про шлюз и локальную модель это
изменение ничего не говорит.

**WebFetch preflight.** Перед загрузкой WebFetch отправляет имя хоста на `api.anthropic.com`, куда
бы ни шли запросы к модели: через шлюз, к облачному провайдеру или на локальный сервер. Её не
отключает даже `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`; для этого есть `skipWebFetchPreflight: true`.

**Codex CLI 0.166.0 для сравнения** (смысл ключей не переносится один к одному):

| Что | Claude Code | Codex |
|---|---|---|
| свой адрес модели | `ANTHROPIC_BASE_URL` | `model_providers.<id>.base_url`, `wire_api` только `responses` |
| локальная модель | не поддерживается вендором | `--oss` и `oss_provider` |
| веб-поиск | deny `WebSearch` | `web_search = "disabled"` (по умолчанию `"cached"`) |
| сеть в песочнице | `sandbox.network.*` | `sandbox_workspace_write.network_access` |
| аналитика | `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `[analytics] enabled = false` |
