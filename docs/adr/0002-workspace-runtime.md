# ADR-0002: Рабочие места: локальный Docker, один контейнер на урок

- Status: Proposed (уточняется в LEARN-задаче "сервис рабочих мест")
- Date: 2026-10-27
- Issue: (bootstrap)

## Context
Обучение идёт полностью через веб. Курс про работу с агентами, значит практика требует
настоящего окружения: shell, git, агентский CLI, репозиторий. Пользователь один, платформа
работает локально. Интернет может быть нестабильным.

## Decision
- Вся платформа запускается через `docker compose` на компьютере ученика.
- `services/workspace` управляет контейнерами через Docker Engine API (dockerode). Только он
  имеет доступ к `docker.sock`.
- Один контейнер на пару (ученик, урок). Файлы в именованном volume, переживают перезапуск.
- Лимиты: CPU, память, pids; non-root; без `--privileged`; без docker socket внутри; сеть
  наружу разрешена (агенту нужен API модели), к внутренним сервисам нет.
- Терминал: `docker exec` с TTY поверх WebSocket.
- Проверки выполняются в контейнере; `checks/` монтируется read-only только в процесс грейдера
  на время проверки. hidden-task выполняется в отдельной копии рабочего места.
- Слой `WorkspaceRuntime` (интерфейс) отделяет логику от Docker, чтобы позже можно было
  перейти на VPS или облачные песочницы (E2B, Daytona) заменой адаптера.

## Alternatives considered
- Облачные песочницы сразу: быстрее старт, но платно, зависимость от сервиса и интернета.
- VPS: доступ откуда угодно, но агент с shell на сервере в интернете требует серьёзной
  изоляции; не нужно для одного пользователя.
- Pyodide в браузере: не подходит, нужен настоящий shell и агентский CLI.

## Consequences
- Нужен Docker Desktop (или аналог) на машине ученика.
- Сервис рабочих мест становится самым сложным компонентом. Он реализуется в LEARN-задачах.
